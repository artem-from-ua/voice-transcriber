# Перевірка proofread на спірних сегментах

Для кожного сегмента нижче послухай аудіо в зазначеному діапазоні
часу та постав **рівно одну** позначку — `better` / `worse` / `neutral`:

- **better** — proofread виправив реальну помилку ASR: ASR видав
  нісенітницю (`корище`, `контролуси`, `твими`), очевидно неправильно
  розчув технічний термін (`HugginsFace` → `Hugging Face`), або
  згенерував граматично неможливу форму, і proofread відновив те,
  що мовець насправді сказав.
- **worse** — proofread змінив текст, який не потребував виправлення,
  або відсунув його далі від того, що сказав мовець. Сюди входить:
    - заміна слова на синонім (наприклад `чуваки` → `хлопці`), коли
      ASR і так правильно зафіксував те, що пролунало;
    - перетворення розмовної форми на літературну чи навпаки, коли
      ASR-варіант уже відповідав мовленню;
    - введення регіонального / нестандартного варіанта, коли ASR
      мав загальновживану форму для цього контексту (типово для
      IT-сленгу — наприклад `продуктовий` → `продуктівий`).
- **neutral** — різниця незначна: пунктуація, регістр літер,
  взаємозамінні вказівні займенники, або правдоподібний здогад на
  спотвореному сегменті, який не вдається верифікувати з аудіо.

Керівний принцип: мета цього інструменту — фіксувати **реальну,
живу українську розмову як її було сказано** (див. CLAUDE.md, розділ
"Project goal"). Ми **не** хочемо, щоб proofread нав'язував літературні
норми, замінював слова на синоніми чи "причісував" мову. Єдина його
робота — виправляти помилки ASR. Усе понад це — регресія.

Після проставлення позначок виконай:
    python scripts/proofread-classify.py parse-marks \
        --marks-file <цей-файл> \
        --judge-marks docs/measurements/57/judge-marks.json \
        --output docs/measurements/57/final-table.md
